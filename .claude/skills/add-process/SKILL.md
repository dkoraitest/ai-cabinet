# Добавить процесс

Процесс в кабинете: регулярная работа человека, которую он описал на первом воркшопе и сохранил скиллом на втором. У процесса четыре места:

- `input/<имя>/`: файлы человека, их кладёт он сам;
- `processes/<имя>/`: описание `process.json` и программа процесса `run.py`, их пишешь ты;
- `output/<имя>/`: результат `result.json` (по нему рисуется карточка) и, если нужно, файл Excel;
- карточка на странице «мой кабинет»: название, время запуска, итог, таблица и кнопка «Запустить».

`<имя>` здесь и дальше: имя папки процесса латиницей (`svodka-prodazh`). Все пути и команды указаны от корня кабинета, где лежит `CLAUDE.md`.

Веди по шагам ниже, по одному: задал вопрос, дождись ответа. Человеку говори «программа процесса», слова «скрипт», «код», «сервер», «порт» не используй.

## 1. Скилл

Посмотри, какие скиллы человека ты видишь: папки в `.claude/skills/` и скиллы в своём списке, кроме скиллов курса (about-me, setup-check, update-cabinet, add-process, run-process, demo-process). Спроси окном «Какой скилл со второго воркшопа берём за основу?». Варианты: до двух скиллов человека по имени, «Вставлю текст скилла», «Скилла нет». Если скиллы человека есть, первым с пометкой «(рекомендую)» поставь первый из них, иначе «Вставлю текст скилла».

- **Скилл по имени.** Прочитай его текст: файл `.claude/skills/<папка>/SKILL.md`, а если файла в кабинете нет, загрузи скилл инструментом Skill. Задачу из скилла сейчас не выполняй: он нужен как описание процесса. В `process.json` в поле `skill` запишешь папку скилла или, если файла в кабинете нет, его имя: запуск фразой загрузит его так же.
- **Вставлю текст скилла.** Скажи: «Вставьте текст скилла сюда. Он лежит во вкладке **Chat** (чат) → **Customize** (настройка) → **Skills** (скиллы): откройте свой скилл и скопируйте текст.» Дождись текста и сохрани его в `.claude/skills/<папка>/SKILL.md`, папка латиницей через дефис по смыслу скилла. В начале файла нужен блок с `name` (как у папки) и `description` (что делает и какими фразами запускается): если блока нет, допиши его; если есть, поправь в нём только `name`. Остальной текст сохрани как есть. Папку отдельно не создавай: запись файла создаст её сама. Перед записью скажи ровно: «Сейчас Claude попросит разрешение записать файл в папку .claude/skills. Это ваш новый скилл, нажмите «Allow» (разрешить).» После записи проверь, что файл есть, и назови путь.
- **Скилла нет.** Предложи описать процесс по формуле «Сцена + Задача + Правила». Если файл «обо мне» заполнен, черновик собери сам по одной из трёх задач оттуда, покажи и спроси «так?». Если в нём заглушка или файла нет, спроси обычным текстом: «Опишите процесс своими словами: что делаете, из каких файлов и что должно получиться.» и собери черновик по ответу. После согласия сохрани его скиллом, как вставленный текст, с той же фразой про окно разрешения.

## 2. Название

Предложи название по скиллу: коротко по-русски, как будет на карточке, и имя папки латиницей: строчные буквы, цифры и дефис, до 40 знаков. Покажи одной строкой: «Процесс «Сводка продаж по АЗС», папка `svodka-prodazh`. Так?» Если `processes/<имя>/` уже есть, это другой процесс: предложи другое имя папки. Скажи, что папки руками переименовывать не нужно: процесс запускается по русскому названию.

## 3. Файлы

Запусти `node tools/processes.mjs input <имя>`: она создаёт папку `input/<имя>/`, открывает её в Проводнике и печатает полный путь. Сам эту папку не создавай и ничего в `input/` не копируй: файлы туда кладёт человек. Скажи: «Открыл папку <путь из вывода целиком, без сокращений>. Скопируйте туда файлы процесса и напишите «готово».» Если папка не открылась, человек откроет её по пути. Дождись «готово».

Потом посмотри, что лежит в папке: `node tools/processes.mjs input <имя> --no-open`. Папка пуста: назови путь ещё раз и попроси проверить, туда ли положены файлы. Таблицы (csv, xlsx, выгрузки 1С) открывай через `python tools/read_table.py "input/<имя>/<файл>"`: `--sheet` покажет другой лист xlsx, `--rows 30` больше строк. Документы и текст читай сам. Свои команды Python не запускай ни здесь, ни дальше: каждая спрашивает окно разрешения. Расчёт проверяй запуском программы процесса, он идёт без окна. Коротко скажи, что видишь: листы, столбцы шапки, число строк, период данных, если он виден. Кодировку и разделитель человеку не называй. Если в файле нет того, что нужно скиллу (например, столбца с литрами), скажи об этом здесь. Спроси: «Так? Это нужные файлы?»

Эти файлы положил человек: действуют правила кабинета о данных, вопрос о коммерческих данных задай один раз и до расчёта. Исключение: файл с пометкой «копия файла учебного кейса» в выводе команды выше (его содержимое совпадает с файлом из `input/case-azs/data/`). Он учебный: вопрос не нужен, а дата расчёта по легенде кейса.

## 4. Результат

Спроси одним окном:

- «Какой результат нужен?» (можно несколько): «Таблица», «Светофор», «Итог одной строкой». Рекомендуемый по скиллу первым.
- «Нужен файл Excel с результатом?»: «Нет, хватит карточки», «Да». Рекомендуемый по скиллу первым.
- Для светофора: «От какой даты считать?»: «От дня запуска», «От даты в данных (отчётная дата в файле)»; рекомендуй по скиллу. Пороги цветов предложи сам по скиллу и спроси «так?».

На копиях файлов учебного кейса дату не спрашивай: «сегодня» по легенде 21.09.2026 (или дата задачи кейса из `input/case-azs/tasks/`). Запиши её в программу постоянной, как в демо, и назови человеку.

Реши, кто выполняет процесс:

- программа (`kind: script`): всё считается по файлам: суммы, сравнения, сроки, сверки. Это обычный случай;
- сам Claude (`kind: claude`): нужно понимать смысл текста: разложить обращения по темам, написать черновик письма. Тогда скажи: «Этому процессу нужен сам Claude, поэтому на карточке вместо кнопки будет подсказка с фразой запуска.»

## 5. Программа процесса и первый запуск

До первой записи, отдельным сообщением перед ней, скажи: «Сейчас Claude попросит разрешение записать программу процесса в папку processes. Проверьте, что путь в окне ведёт внутрь кабинета (ai-cabinet), и нажмите «Allow» (разрешить).» Окно появляется на каждый файл и на каждую правку.

`processes/<имя>/process.json`:

```json
{
  "title": "Сводка продаж по АЗС",
  "phrase": "запусти сводку продаж по АЗС",
  "kind": "script",
  "skill": "svodka-prodazh",
  "input": "input/svodka-prodazh/",
  "output": "output/svodka-prodazh/"
}
```

`phrase`: «запусти» и название в той форме, как его скажут. `skill`: папка скилла из шага 1.

Для `kind: script` напиши `processes/<имя>/run.py` по образцу ниже. Правила:

- Расчёт по скиллу и ответам шага 4. Столбцы ищи по названию из шапки, которую показал `read_table.py`, не по номеру.
- Вход: самый свежий файл нужного типа в `input/<имя>/` (функция `newest_input` в образце), его имя в итоге. Так новый файл за другой период подхватится сам. Если нужны несколько разных файлов, различай их по столбцам или по части имени, которую подтвердил человек.
- Не выдумывай: значение, которого нет или которое не читается числом, это `None`, не ноль. Пропуски не досчитывай и средним не заполняй. Пропуск портит только то, что из него считается: нет литров в одной строке, значит у литров этой АЗС `None`, а её выручку и выручку сети считай, если выручка есть во всех строках.
- Ячейка с `None` на карточке пустая. Строке с пропуском ставь `row_status` `grey` (подпись «нет данных»), а в итоге скажи, чего не хватает: «нет данных о литрах АЗС-03 за 15.09.2026».
- Даты пиши как в данных, период бери из данных. Дата расчёта: как решили в шаге 4, на файлах кейса дата легенды. Если в данных своя отчётная дата, бери её; дату компьютера там не подставляй. Дату расчёта назови в итоге («на 21.09.2026»).
- Excel, если нужен: как в образце курса `templates/processes/svetofor-dogovorov/run.py` (функции `write_excel` и `replace_file`): запись через временный файл, а если файл открыт в Excel, понятная строка «закройте его в Excel» и код выхода 3.
- Понятная причина остановки (нет файла, нет нужного столбца): одна строка по-русски, код выхода 2, без трейсбека.
- Только стандартный Python, openpyxl и `tools/read_table.py`; без интернета и без файлов вне кабинета.

```python
"""<Название процесса>: <что считает, одной фразой>.

Вход: самый свежий файл в input/<имя>/. Выход: output/<имя>/result.json (карточка).
Запуск: кнопка «Запустить» на странице или node tools/processes.mjs run <имя>
"""
import json
import os
import sys
from datetime import datetime
from pathlib import Path

SLUG = "<имя>"
TITLE = "<Название процесса>"
LIMIT = 10 ** 6  # сколько строк данных читать; в файле больше: итог об этом скажет
ROOT = Path(__file__).resolve().parents[2]  # processes/<имя>/run.py: корень кабинета
sys.path.insert(0, str(ROOT / "tools"))
import read_table  # кодировка, шапка и листы как у просмотра таблиц


class StopRun(Exception):
    """Понятная человеку причина остановки: строка по-русски, код выхода 2."""


def newest_input(exts=(".csv", ".xlsx", ".txt")):
    folder = ROOT / "input" / SLUG
    files = [p for p in folder.glob("*") if p.is_file() and p.suffix.lower() in exts
             and not p.name.startswith(("~$", "."))]
    if not files:
        raise StopRun(f"В папке input/{SLUG} нет файла. Положите файл и запустите расчёт снова.")
    # Когда файл появился в папке или изменился: копия из Проводника сохраняет старую дату изменения.
    return max(files, key=lambda p: max(p.stat().st_mtime, p.stat().st_ctime))


def number(text):
    """Число из ячейки: «1 234,5» или «1234.5». Не число: None."""
    # split() без аргументов убирает любые пробелы, и неразрывный между разрядами в выгрузках 1С тоже.
    t = "".join(str(text).split()).replace(",", ".")
    try:
        return float(t) if t else None
    except ValueError:
        return None


def write_result(result):
    out = ROOT / "output" / SLUG
    out.mkdir(parents=True, exist_ok=True)
    tmp = out / "result.json.tmp"
    tmp.write_text(json.dumps(result, ensure_ascii=False, allow_nan=False, indent=2), encoding="utf-8")
    os.replace(tmp, out / "result.json")


def main():
    src = newest_input()
    table = read_table.analyze(src, None, LIMIT)  # лист: второй аргумент (номер с 1 или имя)
    columns, rows = table["columns"], table["rows"]  # строки данных, значения текстом
    # ... расчёт по скиллу ...
    summary = f"... Файл {src.name}."
    if table["data_rows"] > len(rows):
        summary += f" Внимание: в файле {table['data_rows']} строк, посчитаны первые {len(rows)}."
    result = {
        "title": TITLE,
        "updated_at": datetime.now().astimezone().isoformat(timespec="seconds"),
        "status": "green",
        "summary": summary,
        "columns": ["..."],
        "rows": [["..."]],
    }
    write_result(result)
    print(result["summary"])


if __name__ == "__main__":
    for stream in (sys.stdout, sys.stderr):
        stream.reconfigure(encoding="utf-8")
    try:
        main()
    except (StopRun, read_table.UserError) as e:
        print(e, file=sys.stderr)
        sys.exit(2)
```

### Схема результата

`output/<имя>/result.json`, по нему страница рисует карточку:

- `title`: название процесса; `updated_at`: время расчёта в формате ISO с часовым поясом;
- `status`: цвет карточки `green`, `yellow` или `red`. Светофор: `red`, если есть красные строки, иначе `yellow`, если есть жёлтые, иначе `green`. Таблица и итог: `green`; `yellow` или `red`, только если скилл сам задаёт тревогу (например, падение больше 20%). Строки «нет данных» (`grey`) и пометки (`info`) цвет карточки не меняют ни у какого процесса: о них говорит итог;
- `summary`: итог одной строкой;
- `columns`: названия столбцов; `rows`: строки, в каждой столько значений, сколько столбцов: текст, число или `None`. Для итога одной строкой оба списка пустые;
- `row_status` (необязательно, по одному на строку): `green`, `yellow`, `red`, `grey` («нет данных»), `info` (пометка без цвета, её текст в `row_note`);
- `row_note` (необязательно): подпись строки или `None`;
- `files` (необязательно): файлы результата, только `output/<имя>/...`.

Пиши файл только через `json.dumps(..., ensure_ascii=False, allow_nan=False)`: `NaN` ломает карточку.

Для `kind: claude` программы нет. Первый запуск делаешь сам: выполни задачу скилла на файлах из `input/<имя>/` и запиши `output/<имя>/result.json` по той же схеме.

Для `kind: script` запусти `node tools/processes.mjs run <имя>` с ограничением времени 6 минут (timeout 360000): расчёт может идти до 5 минут. Человеку скажи просто «запускаю расчёт».

- «Готово: ...»: сверь итог с тем, что показал `read_table.py`: число строк, названия, порядок цифр. Не сходится: ищи ошибку в программе.
- «не удался», «не записала», «не годится для карточки»: по строкам из вывода поправь `run.py` (снова окно разрешения) и запусти ещё раз. После двух неудачных попыток простыми словами скажи, что не так, и предложи позвать тренера. Текст ошибки Python человеку целиком не показывай.

Потом, для любого `kind`, запусти `node tools/processes.mjs list`. «Готово» человеку говори, только когда у процесса есть строка «Результат:» со свежим временем и нет строки «Ошибка». Назови итог одной строкой и путь `output/<имя>/result.json`, файл Excel, если он есть.

## Если что-то пошло не так

Вопросы «почему процесс не запустился», «почему нет данных», «проверь, где лежат файлы процесса» в новом разговоре разбирает скилл run-process; здесь, в том же разговоре, отвечай так:

- Человек нажал **Deny** (запретить) или окно закрылось: другим способом файл не записывай (ни командой, ни через другую папку). Скажи, что без разрешения сохранить не получится, и предложи сказать «попробуй ещё раз».
- «Проверь, где лежат файлы процесса»: запусти `node tools/processes.mjs input <имя> --no-open` и назови папку и файлы в ней.
- «Почему процесс не запустился»: прочитай `output/<имя>/last-run.log` и скажи простыми словами, что случилось.
- «Почему нет данных»: скажи, каких столбцов или значений нет в файле.
