# Проверка сетапа

Задача: убедиться, что у человека всё готово к работе в кабинете, и закончить понятным чек-листом. На занятии этот чек-лист смотрит тренер. Человек не разработчик: сырой вывод команд не показывай, пересказывай своими словами.

Сам среду не чини. Можно один раз повторить проверку, например после того как человек закрыл файл в Excel. Программы не устанавливай, системные настройки, переменные среды и настройки сети не меняй. Такие проблемы решает ИТ, твоя часть в том, чтобы понятно их записать. Исключение одно: библиотеки Python для Excel и Word ты ставишь сам, если человек согласен (раздел «Библиотеки Python»).

Все пути и команды здесь указаны от корня кабинета, где лежит `CLAUDE.md`. Папка скилла тут ни при чём.

Порядок такой. Проверку среды, страницу, модель и файлы учебного кейса сделай сам, строго по очереди, и расскажи о них одним сообщением. Потом вопросы человеку одним окном. В конце итог. Внутренний порядок человеку не пересказывай и шаги не нумеруй.

## Проверка среды

Запусти из папки кабинета `node tools/check.mjs` и дождись конца. В выводе «✓» значит всё хорошо, «!» предупреждение (работать можно), «✗» проблема. После стрелки «→» идёт подсказка.

Расскажи итог в двух-трёх фразах:

- Только «✓» и «!»: среда в порядке. Предупреждение «В папке input пока нет файлов» человеку не пересказывай: свой файл на этом занятии не нужен, учебный кейс лежит в подпапке `input/case-azs/`.
- Для каждого «✗» скажи простыми словами, что не работает, и приведи подсказку из вывода дословно: её можно показать ИТ. Про библиотеки Python так не делай, для них свой раздел ниже.
- Если команда не запустилась совсем (например, не найден node), значит, на компьютере нет Node.js. Это вопрос к ИТ. Остальное всё равно пройди.

## Страница

Если страница уже запущена в этом разговоре, второй раз её не запускай: назови адрес, который уже есть, и попроси открыть его в браузере. Иначе, когда проверка среды закончилась, запусти `node tools/serve.mjs --open` фоновой задачей (параметр run_in_background у Bash), ровно этой строкой, без `&`, `cd` и перенаправления вывода; человеку скажи просто «запускаю страницу». Дождись строки «Страница работает: http://127.0.0.1:...» и назови адрес из неё целиком, с секретной частью после номера. Адрес бери только из этой строки: проверка среды поднимает страницу ненадолго и на своём порту, её адрес к делу не относится. Страница должна сама открыться в браузере; если не открылась, адрес можно вставить в адресную строку браузера. Если вместо адреса появилась ошибка, перескажи её своими словами.

## Модель

Назови модель, на которой ты сейчас работаешь (она указана в твоих системных сведениях). Если это Sonnet, всё в порядке. Если другая, попроси переключить на Sonnet в выборе модели в окне Claude: на занятиях работаем на Sonnet, она быстрая и бережёт лимиты.

## Файлы учебного кейса

Свой рабочий файл на этом занятии не проси: чтение файлов проверяем на учебном кейсе.

1. Посмотри, что лежит в `input/case-azs/data/`, и назови несколько файлов: «Вижу учебный кейс: продажи АЗС, акт сверки, реестр договоров...». Полный список не нужен.
2. Открой одну таблицу: `python tools/read_table.py "input/case-azs/data/sales_azs_1c.csv" --rows 3` (если `python` не запускается, то же с `py`, на Mac с `python3`). Покажи коротко, что прочитал: какие столбцы, сколько строк, одну-две первые строки. Кейс выдуманный, предупреждение о коммерческих данных здесь не нужно.

Если Python не готов и таблица не открылась, прочитай первые строки `input/case-azs/README.md`: чтение файлов из `input` проверено и так. Если папки `input/case-azs/` нет или она пуста, пункт про input будет «✗».

## Библиотеки Python

Если в проверке среды «✗» стоит у библиотек Python для Excel и Word, а сам Python в порядке, скажи: «Библиотек Python для Excel и Word пока нет. Могу поставить их сам, это займёт минуту.» Спроси, ставить ли, четвёртым вопросом в окне из раздела ниже: «Поставить библиотеки для Excel и Word сейчас?»: «Да, поставь (рекомендую)», «Нет, позже».

Если человек согласен, скажи: «Сейчас Claude попросит разрешение на установку, нажмите «Allow» (разрешить).» Выполни ровно то, что стоит после слова «выполните» в строке про библиотеки Python для Excel и Word, например `python -m pip install --user openpyxl python-docx`. Подсказки из других строк проверки (например, про `git config`) сам не выполняй: их показывают ИТ. Потом ещё раз запусти `node tools/check.mjs` и посмотри строку про библиотеки. Если установка упала с ошибкой сертификата, сети или прокси, второй раз не пробуй: это вопрос к ИТ, сохрани точный текст ошибки для итога.

Если «✗» у самого Python, библиотеки не ставь: Python ставит ИТ.

## Вопросы человеку

Перед окном скажи одной фразой, что последний пункт человек делает сам: «Если ещё не входили на платформу курса, откройте в браузере её адрес и войдите по рабочей почте. При первом входе платформа спросит код потока: тренер покажет его на экране.» Почту и код потока не спрашивай.

Задай одним всплывающим окном (если окна нет, текстом, варианты списком):

- «Страница открылась в браузере?»: «Да, вижу «Мой кабинет»», «Нет, не открылась».
- «Под какой почтой вы вошли в Claude?»: «Под рабочей», «Под личной», «Не знаю, где посмотреть».
- «Вы вошли на платформу курса по рабочей почте?»: «Да», «Нет, почта не принимается», «Ещё не входил».
- Четвёртый вопрос, только если нужны библиотеки Python (раздел выше).

Если человек не знает, где посмотреть почту: в приложении Claude она видна в меню профиля, оно открывается по нажатию на имя или инициалы внизу слева; в VS Code это учётная запись в панели Claude. Не нашёл и там: отметь пункт «✗» с пометкой «не проверено» и предложи спросить тренера. Если страница не открылась, дай адрес ещё раз, чтобы вставить его в браузер вручную.

## Итог

Покажи чек-лист из восьми строк ровно в таком виде, слово в слово. Меняй только знак в начале строки: «✓» или «✗».

```
✓ Вход в Claude под рабочей почтой
✓ Кабинет ai-cabinet развёрнут
✓ Claude видит файлы кабинета
✓ Claude читает файлы из папки input
✓ Модель Sonnet
✓ Страница открывается на localhost
✓ Python и библиотеки для Excel и Word готовы
✓ Вошёл на платформу курса по рабочей почте
```

Как ставить отметки:

- вход под рабочей почтой: по ответу человека;
- кабинет развёрнут: проверка среды запустилась из этой папки, Node.js и Git найдены, запись файлов работает;
- Claude видит файлы кабинета: ты смог показать, что лежит в `input/case-azs/`;
- Claude читает файлы из папки input: ты показал первые строки таблицы кейса (или README кейса);
- модель: по тому, что ты назвал выше;
- страница: она запустилась и человек увидел её в браузере;
- Python и библиотеки: в проверке среды «✓» у Python и у библиотек, сразу или после установки;
- платформа курса: «✓» при ответе «Да» или том же своими словами («да, вошла»); «Нет, почта не принимается», «Ещё не входил» и любой другой ответ дают «✗».

Пункт, который проверить не удалось, отмечай «✗», а в строке под ним напиши «не проверено» и что сделать.

Под каждым «✗» одна строка: что сделать. Бери совет по пункту:

- вход под личной почтой: выйти из Claude и войти под рабочей, места Team выданы на рабочие адреса;
- кабинет не развёрнут: Node.js или Git не найден, позовите тренера, их ставит только ИТ; нет записи в папку, позовите тренера, кабинет нужно переставить в папку пользователя (Документы);
- Claude не видит или не читает файлы кейса: откройте в Claude папку `ai-cabinet`; если кейса в ней нет, скажите «обнови кабинет»;
- модель не Sonnet: переключите на Sonnet в выборе модели в окне Claude;
- страница: скажите «открой страницу» ещё раз; не помогло, позовите тренера, это вопрос к ИТ;
- Python: позовите тренера, Python ставит ИТ; библиотеки не поставились из-за сертификата или сети, позовите тренера, это прокси компании, вопрос к ИТ;
- библиотеки не ставили («Нет, позже»): сводная на csv работает и без них, для Excel и Word они нужны; поставить: скажите «проверь сетап»;
- «Нет, почта не принимается»: проверьте адрес платформы и написание рабочей почты; не помогло, позовите тренера: он проверит, есть ли почта в списке программы, и добавит её; если платформа не принимает код потока, сверьте его с экраном;
- «Ещё не входил»: откройте адрес платформы и войдите по рабочей почте, код потока при первом входе тренер покажет на экране.

«Позовите тренера» в этих советах значит: позовите тренера или ассистента, а если вы не на занятии, напишите им. Так и пиши человеку.

Сразу после чек-листа скажи правило Практики дословно: «Чужие скиллы не ставим. Добавляйте только свои скиллы и те, что даёт курс. Скилл из интернета или от знакомых может содержать команды, которые выполнятся на вашем компьютере без вашего ведома».

Если человек работает в VS Code (спроси или пойми по разговору: панель Claude внутри VS Code), расскажи, как включить автоприём правок: откройте **File** (файл), потом **Preferences** (настройки), потом **Settings** (настройки), в поиске введите «initialPermissionMode» и в параметре `claudeCode.initialPermissionMode` выберите `acceptEdits`. После этого начните новый разговор в папке кабинета, настройка действует на новые разговоры. В приложении Claude этот шаг не нужен.

Если есть хоть один «✗», сохрани итог в `output/setup-check.md`: чек-лист и точный текст ошибок для тренера и ИТ. Скажи человеку, что этот файл можно показать тренеру.

Если всё «✓», скажи: «Сетап готов. Следующий шаг: скажите «расскажу о себе», и мы заполним файл «обо мне».» Если файл «обо мне» уже заполнен, следующий шаг назови так, как велят правила кабинета для фразы «что дальше».
